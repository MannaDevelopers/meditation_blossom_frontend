# Issue #218: Android 위젯 텍스트 sp→dp 고정 크기 전환 — 구현 계획

**Goal:** Android 위젯(주일 말씀/QT 매일 만나, Large/Small 4종)의 텍스트가 시스템 글꼴 크기 설정(`설정 > 디스플레이 > 글자 크기`)에 곱해져 확대되지 않도록, 사용자가 EditScreen에서 고른 디자인 크기(16/20/24/28pt)와 `Typography` 기본값이 항상 지정한 크기 그대로 렌더링되게 고정한다.

**배경**: [#215](https://github.com/MannaDevelopers/meditation_blossom_frontend/issues/215) 부모 이슈의 sub-issue. [#217](https://github.com/MannaDevelopers/meditation_blossom_frontend/issues/217)과 병행 가능하다고 명시되어 있으나, 현재 main 기준으로 이미 브릿지 저장/Glance 렌더링은 완료되어 있고 이 이슈(폰트 크기 고정)만 미착수 상태다.

**기술적 조사**: Glance `Text`의 `TextStyle.fontSize`는 `TextUnit`(sp 전용, dp 지정 불가)만 받는다. 또한 Glance는 Compose 트리를 직접 그리지 않고 `RemoteViews`로 변환해 런처(호스트) 프로세스가 그리므로, 컴포지션 안에서 `LocalDensity`를 `fontScale = 1f`로 오버라이드해도 최종 렌더링에는 영향이 없다 — `setTextViewTextSize(SP, value)`에 넘어가는 raw sp 숫자는 호스트 프로세스의 시스템 `fontScale`로 다시 곱해지기 때문이다. 따라서 dp 리터럴 전환이 아니라, **의도한 크기를 시스템 `fontScale`로 나눈 sp 값**을 계산해 넘겨야 한다(호스트가 다시 곱하면 상쇄되어 결과적으로 고정 크기 효과). `Context.resources.configuration.fontScale`은 시스템 전역 값이라 앱 프로세스에서 읽은 값이 런처의 값과 동일하다.

**대상 파일**:
- `android/app/src/main/java/app/mannadev/meditation/ui/widget/theme/Type.kt` — `Typography`를 `fontScale` 파라미터를 받는 팩토리로 전환
- `android/app/src/main/java/app/mannadev/meditation/ui/widget/WidgetDesignRendering.kt` — `toBodyTextStyle`/`toTitleTextStyle`/`toIndexTextStyle`에 `fontScale` 파라미터 추가
- `android/app/src/main/java/app/mannadev/meditation/ui/widget/VerseWidgetLarge.kt`, `VerseWidgetSmall.kt`, `QtWidgetLarge.kt`, `QtWidgetSmall.kt` — 각 Content 컴포저블에서 `fontScale` 읽어 위 두 곳에 전달 (4개 파일 모두 이미 `LocalContext` import/사용 중이라 배선만 추가하면 됨)

**타이밍 갭과 대응**: `fixedSp`는 `provideGlance` 실행 시점의 `fontScale`을 읽어 값을 계산한다. 그런데 Glance는 결국 `RemoteViews.setTextViewTextSize(SP, ...)`로 변환되고, 이 sp→px 변환은 **런처(호스트) 프로세스가 RemoteViews를 재적용하는 시점**에 그때그때의 시스템 `fontScale`로 다시 일어난다. Android는 시스템 글꼴 크기가 바뀌면(`CONFIGURATION_CHANGED`) 호스트가 기존 RemoteViews를 앱의 새 데이터 없이도 자동 재적용하므로, "위젯이 이미 화면에 떠 있는 상태에서 설정만 바꾸는" 경우 `fixedSp`가 계산 당시의(바뀌기 전) fontScale을 이미 상수로 굳혀놨기 때문에 상쇄가 깨져 여전히 확대되어 보일 수 있다. 이 갭은 [WidgetPeriodicSyncWorker.kt](android/app/src/main/java/app/mannadev/meditation/widget/WidgetPeriodicSyncWorker.kt)의 1일 주기 동기화로 결국 해소되지만, 즉시 반영을 위해 **MainActivity에서 fontScale 변경을 감지해 즉시 위젯을 갱신**하는 로직을 추가한다(Task 5). `MainActivity`의 `android:configChanges`에 `fontScale`이 포함되어 있지 않아, 앱이 포그라운드에 있는 동안 설정이 바뀌면 시스템이 Activity를 재생성(`onCreate` 재호출)한다 — 이 지점을 훅으로 사용한다. 단, 앱이 완전히 백그라운드/미실행 상태에서 설정이 바뀌는 경우는 이 훅이 실행되지 않으므로 다음 앱 실행 또는 주기 동기화까지는 여전히 지연될 수 있다(허용 범위로 간주).

**Non-goals**: iOS는 대상 아님(이슈 본문 명시). 디자인 값 자체(색상/정렬/배경)는 변경하지 않는다.

**테스트 정책**: 순수 함수(`fixedSp`, `hasFontScaleChanged` 계산)는 `android/app/src/test/`에 단위 테스트 추가. 그 외 Glance 렌더링 자체는 실기기 확인이 필요하다고 이슈에 명시되어 있음 — 이 세션은 에뮬레이터/실기기가 연결되어 있지 않아 **코드 검증은 `./gradlew` 컴파일/유닛테스트까지만** 수행하고, 실기기 QA(시스템 글꼴 최대 설정 후 오버플로우 확인)는 사용자 몫으로 남긴다.

**커밋 정책**: `feature/issue-218` 브랜치. 커밋 메시지 `[ISSUE-218] type: 설명`.

## Self-Review 체크리스트 (구현 후 확인)

- 이슈 본문의 두 옵션("dp 기반 전환" 또는 "fontScale=1f 오버라이드") 중 어느 쪽도 Glance API 제약상 문자 그대로는 불가능해 "fontScale로 나눈 sp 상쇄" 방식을 택함 — 이 기술적 판단과 "위젯이 이미 떠 있는 상태에서 설정만 바꾸면 앱 실행/주기 동기화 전까지는 지연될 수 있다"는 한계를 PR 설명에 명시.
- `Typography` 필드 중 실제 사용되지 않는 것(`title`, `verse`, `book`, `labelLarge`, `headlineSmall`)이 있는지 확인하고, 있다면 스코프 밖이므로 손대지 않음(제거는 별도 이슈).
- `notifyFontScaleChanged()`가 다른 3개 notify 메서드와 달리 "왜 4개 위젯을 한 번에 갱신하는지"(폰트 크기는 콘텐츠 종류와 무관하게 전체에 영향) 이유가 코드만 봐서 명확한지 확인.
