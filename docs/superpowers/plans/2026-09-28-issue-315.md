# Issue #315: 예배시간 설정 시 FCM 수신 즉시가 아닌 실제 예배 시각에 맞춰 말씀 업데이트되도록 개선 — 구현 계획

**Goal:** 특정 예배시간("토요일 오후 5시"/"주일 9시 50분"/"주일 11시 50분"/"주일 2시 30분")으로 설정한 사용자에게는, 실제 그 예배 시각이 되기 전까지는 메인 화면/위젯이 새 주 콘텐츠로 바뀌지 않고 이전 콘텐츠를 유지하다가, 예배 시각이 되는 순간(앱이 꺼져 있어도) 자동으로 전환되게 한다. "전체" 설정은 동작 변경 없음.

**원인 분석 (JS/Android/iOS 3곳 모두 동일한 패턴의 버그):**
- JS `useFCMListener.ts`(isWeeklyEvent 분기)·Android `WeeklySermons.shouldApplyToWidget`·iOS `WorshipSermonSync.shouldApplyWeeklyEvent`는 모두 "사용자 설정 == FCM의 worship_type"이면 **수신 즉시** 화면/위젯에 반영한다. 예배 시각과 무관.
- 더 심각한 경로: `useSermonData.ts`의 `loadLocalData`/`fetchFromServer`/onSnapshot 구독은 **앱을 열 때마다** `weekly_sermons` 캐시에서 설정과 일치하는 문서를 찾아 그대로 화면에 반영한다. FCM 수신 시점 게이팅과 무관하게, 캐시에 이미 저장된 미래 예배 콘텐츠를 앱을 열기만 해도 보여주는 경로라 이 부분이 더 근본적인 수정 대상이다.
- iOS 위젯의 `Provider.getTimeline`(`MeditationBlossomWidget.swift`)은 App Group의 "지금" 슬롯(`displaySermon`) 하나만 읽어 엔트리 1개 + 24시간 뒤 갱신 정책만 사용한다. WidgetKit이 지원하는 "미래 날짜의 여러 엔트리 예약" 기능을 쓰지 않아, NSE가 미리 쓰지 않는 이상 정확한 시각 전환이 불가능하다.
- Android 위젯은 FCM 즉시 반영 + 30분 주기(`updatePeriodMillis`) 백업 갱신만 있고, 그 백업 갱신 시점에 "지금 보여줄 예배가 맞는지" 재계산하는 로직이 없다.

**Tech Stack:** TypeScript/React Native, Kotlin(Android native + Glance widget), Swift(iOS WidgetKit + Notification Service Extension).

**검증 범위 (중요, 정직하게 명시):**

### Task 1: 예배시간 스케줄 판별 순수 함수 (JS, 기준 소스)

**File:** `src/utils/worshipSchedule.ts` (신규)

`WorshipType`별 요일(ISO weekday)/시각 매핑 테이블과, `week`(ISO 8601 "YYYY-Www") + `worship_type`으로부터 실제 예배 datetime을 계산해 "지금 이 시각에 이미 도달했는지"를 반환하는 순수 함수를 추가한다.

```ts
import { WorshipType } from '../types/Sermon';

// 각 예배의 요일(ISO weekday: 월=1 ... 일=7)/시각. WORSHIP_TYPES(src/types/Sermon.ts) 라벨과 1:1 대응.
// Android WorshipSchedule.kt / iOS WorshipSermonSync.swift와 반드시 동일하게 유지한다.
export const WORSHIP_SCHEDULE: Record<WorshipType, { isoWeekday: number; hour: number; minute: number }> = {
  SAT_1700: { isoWeekday: 6, hour: 17, minute: 0 },
  SUN_0950: { isoWeekday: 7, hour: 9, minute: 50 },
  SUN_1150: { isoWeekday: 7, hour: 11, minute: 50 },
  SUN_1430: { isoWeekday: 7, hour: 14, minute: 30 },
};

/** ISO 8601 week string("2026-W37")의 월요일 0시(로컬 타임존)를 반환. 형식이 잘못되면 null. */
export function resolveIsoWeekMonday(week: string): Date | null {
  const match = /^(\d{4})-W(\d{2})$/.exec(week);
  if (!match) return null;
  const year = parseInt(match[1], 10);
  const weekNumber = parseInt(match[2], 10);
  // ISO 8601: 해당 연도 1월 4일이 항상 1주차에 속한다.
  const jan4 = new Date(year, 0, 4);
  const jan4Weekday = jan4.getDay() === 0 ? 7 : jan4.getDay(); // 일=0 -> 7
  const week1Monday = new Date(year, 0, 4 - (jan4Weekday - 1));
  const monday = new Date(week1Monday);
  monday.setDate(week1Monday.getDate() + (weekNumber - 1) * 7);
  monday.setHours(0, 0, 0, 0);
  return monday;
}

/** week + worshipType이 가리키는 실제 예배 시작 datetime(로컬 타임존). 계산 불가하면 null. */
export function resolveWorshipDateTime(week: string, worshipType: WorshipType): Date | null {
  const monday = resolveIsoWeekMonday(week);
  const schedule = WORSHIP_SCHEDULE[worshipType];
  if (!monday || !schedule) return null;
  const result = new Date(monday);
  result.setDate(monday.getDate() + (schedule.isoWeekday - 1));
  result.setHours(schedule.hour, schedule.minute, 0, 0);
  return result;
}

/**
 * week/worshipType이 가리키는 예배 시각에 현재 시각(now)이 이미 도달했는지.
 * week/worshipType 조합을 해석할 수 없으면(방어적으로) true — 판별 불가한 데이터를 영원히
 * 숨기는 것보다 기존 동작(즉시 반영)으로 폴백하는 쪽이 안전하다.
 */
export function hasWorshipTimeArrived(
  week: string | undefined,
  worshipType: WorshipType | undefined,
  now: Date = new Date(),
): boolean {
  if (!week || !worshipType) return true;
  const scheduled = resolveWorshipDateTime(week, worshipType);
  if (!scheduled) return true;
  return now.getTime() >= scheduled.getTime();
}
```

### Task 2: `sermonService.ts` — 게이팅 헬퍼 및 `syncSelectedSermonToWidget` 수정

**File:** `src/services/sermonService.ts`

`weekly_sermons` 캐시에서 사용자 설정에 맞는 문서를 찾아도, 그 문서의 예배 시각이 아직 안 됐으면 **이미 화면에 보이고 있는 이전 콘텐츠를 그대로 유지**해야 한다는 규칙을 한 곳에 모은다.

```ts
import { hasWorshipTimeArrived } from '../utils/worshipSchedule';

/**
 * weekly_sermons 캐시에서 사용자 설정에 맞는 문서를 찾되, 그 예배 시각이 아직 안 됐으면
 * currentlyDisplayed(이미 화면/위젯에 보이던 콘텐츠)를 그대로 반환한다([ISSUE-315] —
 * FCM은 예배 시각보다 훨씬 먼저 도착하므로, 시각이 되기 전엔 절대 새 콘텐츠를 노출하지 않는다).
 * '전체' 설정은 이 함수의 대상이 아니다(호출자가 별도 레거시 경로로 처리).
 */
export function selectGatedWeeklySermon(
  weeklySermons: Sermon[],
  worshipType: WorshipType,
  currentlyDisplayed: Sermon | null,
  now: Date = new Date(),
): Sermon | null {
  const candidate = weeklySermons.find(s => s.worship_type === worshipType) || null;
  if (!candidate) return currentlyDisplayed;
  if (!hasWorshipTimeArrived(candidate.week, candidate.worship_type, now)) {
    return currentlyDisplayed;
  }
  return candidate;
}
```

`syncSelectedSermonToWidget`를 이 헬퍼를 쓰도록 수정한다. 기존 "캐시에 아예 없으면 weekly[0]으로 폴백"하던 동작(무관한 데이터 품질 이슈 대응)은 유지하되, 게이트는 "정확히 일치하는 문서를 찾은 경우"에만 적용한다:

```ts
export async function syncSelectedSermonToWidget(worshipType: WorshipType): Promise<void> {
  let weekly = await fetchLatestWeeklySermonsFromAsyncStorage();
  if (weekly.length === 0) {
    try {
      weekly = await fetchLatestWeeklySermonsFromServer();
      if (weekly.length > 0) await saveWeeklySermonsToAsyncStorage(weekly);
    } catch (e) {
      logger.warn('syncSelectedSermonToWidget: 로컬 캐시가 비어 서버 폴백 조회 시도했으나 실패 (오프라인?)', e);
    }
  }
  if (weekly.length === 0) return;

  const currentlyDisplayed = await fetchLatestSermonFromAsyncStorage();
  const matched = weekly.find(s => s.worship_type === worshipType);
  const gated = matched
    ? selectGatedWeeklySermon(weekly, worshipType, currentlyDisplayed)
    : weekly[0]; // 완전히 일치하는 문서가 없는 기존 폴백은 그대로 둔다
  if (!gated) return;

  await saveSermonToAsyncStorage(gated);
  await pushSermonToWidget(gated);
}
```
