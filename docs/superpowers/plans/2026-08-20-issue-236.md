# Issue #236: QT(매일 만나) 위젯 디자인 - 콘텐츠별 별도 저장 + EditScreen 소스 필 — 구현 계획

**Goal:** `WidgetDesign`을 주일 말씀/QT가 공유하던 것을 콘텐츠 타입별로 완전히 독립적으로 저장하도록 분리한다. Android 저장 계층(SharedPreferences 키·갤러리 배경 파일·인메모리 상태)을 콘텐츠별로 나누고, RN `EditScreen`에 콘텐츠 소스 필(주일 말씀/매일 만나)을 추가해 두 소스의 draft를 독립적으로 편집·저장할 수 있게 한다. QT 위젯이 저장된 디자인을 실제로 *렌더링*하는 작업(#217의 QT 버전)은 이번 스코프에 포함하지 않는다 — 이번 이슈는 저장 계층 분리와 EditScreen UI까지.

**⚠️ 빌드 검증 범위**: 이 작업 환경은 Windows다. Android는 Gradle이 로컬에서 동작하므로 Kotlin 컴파일/단위테스트를 직접 검증한다. iOS는 Xcode가 없어 Swift 변경은 기존 패턴을 따르되 컴파일 확인은 못 한다(#204와 동일 상황) — PR에 리뷰어용 체크리스트로 남긴다.

**Architecture 결정**: 이슈 본문이 "sermonDesignState/qtDesignState 두 StateFlow로 분리 vs 타입 파라미터 단일 API 중 구현 시 결정"이라고 열어뒀다. `WidgetDesignPrefsDataSource`의 비트맵 다운샘플링/JSON 인코딩 로직(약 100줄)이 두 콘텐츠 타입 간 완전히 동일하므로, **클래스를 복제하지 않고 Hilt `@Qualifier`(`@SermonDesign`/`@QtDesign`)로 같은 구현체를 콘텐츠 타입별 파라미터(prefs 키·배경 파일명)만 다르게 준 두 개의 싱글턴 인스턴스로 바인딩**한다. `SermonRepository`/`QtRepository`처럼 완전히 다른 클래스로 쪼개면 로직 중복이 생기고, 문자열 타입 파라미터를 받는 단일 API로 통일하면 이슈 본문이 지적한 대로 컨벤션(sermon/qt를 별도 브릿지 메서드로 분리하는 기존 패턴)과 어긋난다. Qualifier 방식이 두 요구사항(로직 재사용 + 기존 sermon/qt 분리 브릿지 컨벤션)을 동시에 만족한다.

**Tech Stack:** Kotlin (Hilt DI, Glance AppWidget), TypeScript (React Native, styled-components), Swift(스텁만).

**테스트 정책:** Android는 `WidgetDesignRepositoryImplTest`(기존, 변경 없음 — Impl 자체 로직은 콘텐츠 타입과 무관)에 더해 `WidgetDesignPrefsDataSource`가 콘텐츠 타입별로 다른 키/파일명을 쓰는지 확인하는 신규 유닛 테스트 추가. RN은 `EditScreen`이 훅 기반이 아니라 화면 컴포넌트라 기존 컨벤션상 별도 테스트가 없음(`__tests__/WidgetDesign.test.ts`는 순수 함수만 다룸, 스키마 불변이라 수정 불필요) — 수동 QA로 검증.

**커밋 정책:** `feature/issue-236` 브랜치, 커밋 메시지 `[ISSUE-236] type: 설명`.

      @Singleton

### Task 9: iOS — QT 디자인 브릿지 스텁 (TurboModule 빌드 유지용)

**Files:**
- `ios/WidgetUpdateModule.swift`
- `ios/WidgetUpdateModule.mm`

Task 4에서 Spec에 `onQtWidgetDesignUpdated`를 추가하면 iOS TurboModule도 프로토콜을 구현해야 빌드가 깨지지 않는다. 기존 `onWidgetDesignUpdated`(83~96행)와 동일한 최소 스텁 패턴 — 실제 App Group 이미지 처리/렌더링은 별도 iOS 디자인 브릿지 이슈([#220](https://github.com/MannaDevelopers/meditation_blossom_frontend/issues/220) 패턴)에서 진행:

**Swift** (`WidgetUpdateModuleImpl`, `Constants`에 `widgetDesignQtKey` 추가):
```swift
static let widgetDesignQtKey = "widget_design_qt"
...
@objc
func onQtWidgetDesignUpdated(_ designData: String, resolver resolve: @escaping RCTPromiseResolveBlock, rejecter reject: @escaping RCTPromiseRejectBlock) {
  guard let sharedDefaults = Self.appGroupDefaults() else {
    reject("APP_GROUP_ERROR", "App Group을 찾을 수 없습니다.", nil)
    return
  }
  sharedDefaults.set(designData, forKey: Constants.widgetDesignQtKey)
  sharedDefaults.synchronize()
  WidgetUpdateModuleImpl.reloadWidgets()
  resolve(true)
}
```

**ObjC++ 브릿지** (`WidgetUpdateModule.mm`, 기존 `onWidgetDesignUpdated:resolve:reject:` 바로 아래):
```objc
- (void)onQtWidgetDesignUpdated:(NSString *)designData
                         resolve:(RCTPromiseResolveBlock)resolve
                          reject:(RCTPromiseRejectBlock)reject
{
  [_impl onQtWidgetDesignUpdated:designData resolver:resolve rejecter:reject];
}
```
